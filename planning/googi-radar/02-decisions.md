| D7 | 데이터 입력·검수 (R1에서 수정) | 첫 버전은 운영자(사용자 본인)가 직접 입력하는 화면만: 메뉴판 사진과 부위·종류·중량·가격 입력. 다른 사용자의 사진 제보는 홍보를 시작할 때 추가. 가게마다 "메뉴 확인일" 표시, 6개월 경과 시 "오래된 정보일 수 있어요". 자동 인식(OCR)은 첫 버전 제외, 데이터가 많이 쌓이면 추가 | 본인 사용 우선(D13), 잘못된 숫자 하나가 순위를 망침, 손글씨 메뉴판 OCR 품질 | 추천안 동의 + 사용자 추가(OCR 나중), R1 수정 동의 |

| D9 | 플랫폼 | 모바일 웹(앱 설치 없음), 카카오 지도 JavaScript API로 지도 표시. 위치 허용 시 내 주변, 거부 시 동네(주안역·구월동) 직접 선택. 폰 화면 기준 설계(PC에서도 열림). 앱 출시는 사용자 확인 후 판단 | 링크 공유 쉬움(단톡방), 설치·심사 장벽 없음, 빠른 검증 | 추천안 동의 |
| D10 | 성공 기준 (R1에서 수정) | (1) 데이터: 주안역·구월동 상권 각 20곳 이상의 삼겹살·목살 100g당 가격 확보 + 메뉴판 중량 표기 비율 측정 (2) 본인 사용: 2달 동안 고기 먹으러 갈 때 이 서비스로 가게를 고른 횟수 3번 이상 (3) 확장 판단: (2) 달성 시 홍보·사진 제보 기능을 열지 결정. "방문자 30%", "사진 월 10건"은 그 단계의 지표로 연기 | 사용자 혼자 쓰는 단계에서 방문자·제보 지표는 의미 없음 | 추천안 동의 (R1) |
| D11 | 고기 종류 구분 | 같은 부위라도 생고기 / 냉동 / 대패는 서로 다른 메뉴로 구분하고, 같은 종류끼리만 비교한다(삼겹살·목살 모두 적용) | 사용자: "생삼겹이랑 냉동삼겹(+대패삼겹살)이랑 다른 거 아니야? 구분해야 할 거 같아" | 사용자 답 (Q1 해소) |
| D12 | 비교 해석 원칙 | 100g당 가격 숫자만 보여주지 않고, 기준 가격에 비춰 "몇 g 차이가 몇 원 가치인지"를 추론해 어느 가게가 나은지 설명·추천한다. 삼겹살은 주변 가게와 국가 기준(참가격)을, 목살은 주변 가게와 가능한 국가 기준을 쓴다 | 사용자 요청(160g 14,000원 vs 180g 15,000원 예시) | 사용자 답 |
| D13 | 사용 단계 | 당분간 홍보 없이 사용자 본인이 써 보고 이후 확장 여부를 결정한다. 가게 사장님 정정·삭제 요청 기능은 만들지 않음(비목표) | 사용자: "홍보도 할 생각 없고 일단 내가 잘 쓰는지 보고나서 선택할거라서 너무 먼 미래" | 사용자 답 (Q5 해소) |
| D14 | 비교 해석 계산·표시 (D12 세부) | 기준 가격(100g당): 1순위 같은 상권·같은 종류 가게들의 중간값(5곳 미만이면 기준 미표시), 2순위 참고용 참가격 인천 삼겹살 200g 환산가 ÷ 2(생삼겹에만). 목살·냉동·대패는 주변 중간값만. 문구 예: "B가 20g 더 많고 1,000원 더 비싸요. 20g은 이 동네 기준 약 1,700원어치라 B가 약 700원 이득이에요." 100g당 이득 3% 이상이면 "B 추천", 3% 미만이면 "거의 같아요". 중량 미표기는 추정하지 않음(D8 유지) | 동네 가격이 지역 전체 평균보다 판단에 정확, 표본이 적으면 기준이 흔들림 | 추천안 동의 (R2) |
| D15 | 가격 기록 단위 | 1인분 가격이 적힌 메뉴는 1인분 가격(그리고 1인분 중량)으로 기록한다(100g당 가격만 적힌 메뉴는 D17). "2인분 이상 주문"이어도 1인분 가격으로 적는다 | 사용자: "2인분 이상 주문이라고 해도 가격은 1인분 가격으로 적어놓잖아. 1인분 가격으로 적게 해야지" | 사용자 답 (Q3 일부 해소) |
| D16 | 가게 목록 조회·저장 | 고기집 목록은 지도를 볼 때마다 카카오 로컬 API로 실시간 검색해 표시하고 미리 대량 저장하지 않는다. 우리 쪽 저장은 운영자가 메뉴를 입력한 가게만(D23에서 정정) | 카카오의 "데이터 수집용 사용 금지" 답변(Q9). 사용자: "지도를 볼 때마다 검색하는 방식을 써야겠지… 저장하고 싶으면 알아서 저장하라고 하지" | 사용자 답 (저장 범위는 D23에서 확인·정정) |
| D17 | 표기 형식이 다른 가게끼리 비교 | 가게마다 메뉴판 표기 형식이 달라도(A: "100g 8,000원"만, B: "1인분 160g 14,000원"만) 모두 100g당 가격으로 환산해 비교한다. 예: B = 14,000 ÷ 160 × 100 = 8,750원 → A가 100g당 750원(약 8.6%) 저렴. 기록은 메뉴판에 적힌 값 그대로(100g당 가격 및/또는 1인분 중량·가격) 저장하고 환산은 계산으로 한다 | 사용자: "b의 가게의 100g 당 가격을 계산해서 비교하면 되지 않을까?" | 사용자 답 |
| D18 | 동네 기준 가격의 범위 | "같은 상권" = 비교하는 가게들 중심에서 반경 1km 안의 가게 | 3단계 Q-N2에 대한 사용자 답 "1km로 해" | 사용자 답 |
| D19 | 목록 기본 필터 | 삼겹살 · 생고기 · 국내산 | 3단계 Q-N9 추천 | 추천안 동의 |
| D20 | 추천 표시 기준 계산 | 100g당 가격 차이율 = (비싼 쪽 − 싼 쪽) ÷ 비싼 쪽. 3% 이상이면 싼 쪽에 "추천", 3% 미만이면 "거의 같아요" | 3단계 Q-N4 추천 | 추천안 동의 |
| D21 | 이득 문구 계산 기준 (D14 문구 부분 수정) | 늘어난 그램의 가치는 동네 기준가가 아니라 **비교 상대 가게의 100g당 가격**으로 계산한다: 가치 = 중량 차이 × 상대 가게 100g당 가격 ÷ 100, 이득 = 가치 − 가격 차이. 예: A 160g 14,000원, B 180g 15,000원 → "20g을 A에서 사면 1,750원인데 B는 1,000원만 더 받아 B가 750원 이득". 동네 기준가(D14·D18)는 "동네보다 ○% 저렴" 표시에만 사용 | 4단계 독자 테스트: 동네 기준가로 계산하면 이득 문구와 100g당 추천(D20)이 엇갈릴 수 있음. 상대 가게 단가로 계산하면 항상 같은 결론 | 추천안 동의 (4단계) |
| D22 | 지도와 목록의 역할 | 지도: 카카오에서 찾은 고기집을 모두 핀으로 표시. 가격 정보가 있으면 100g당 가격이 적힌 진한 핀, 없으면 회색 핀("정보 없음"). 목록: 필터에 맞는 가게만 100g당 가격 싼 순 + 맨 아래 "중량 미표기" 묶음. "정보 없음" 가게는 목록에 넣지 않음. 필터는 목록과 진한 핀에만 적용, 회색 핀은 항상 표시 | 4단계 독자 테스트: R1("정보 없음"을 목록에 표시)과 R4(기본 필터로 조건 메뉴 있는 가게만)가 충돌 | 추천안 동의 (4단계) |
| D23 | "저장"의 의미 (D16 해석 정정) | 서비스(서버)는 보는 사람의 저장·즐겨찾기를 보관하지 않는다. 보는 사람이 원하면 자기 폰(브라우저)에 즐겨찾기한다. 서버에 저장하는 것은 운영자가 입력한 메뉴 데이터(D7)와 그에 연결된 카카오 장소 ID뿐 | 사용자: "앱이 저장하지 말고, 보는 사람이 원하면 자기 폰에 즐겨찾기하게 둔다" (D16의 "사용자가 저장하기로 고른 가게"는 Claude의 잘못된 해석) | 사용자 답 (4단계) |
| D24 | 같은 조건 메뉴가 여럿일 때와 "숙성" | 순위 단위는 가게(한 가게는 목록에 한 번). 순위·비교에는 그 가게에서 조건(부위·종류·원산지)에 맞는 메뉴 중 100g당 가장 싼 메뉴를 쓰고 메뉴 이름을 함께 표시. 가게 상세에는 조건에 맞는 메뉴를 모두 표시. ## 가정 (미확인)
- A1: 카카오 로컬 API의 `FD6`(음식점) + 키워드("고기", "삼겹살" 등) 검색으로 두 구의 고기집 대부분을 찾을 수 있다.
- A2: 주안역·구월동 상권에 각각 고기집이 20곳 이상 있다.
- A3: 고깃집 메뉴판 상당수에 100g당 가격이나 1인분 중량이 적혀 있다(D10-1에서 측정).
- A4: (확장 단계) 다녀온 사용자가 로그인 없이도 메뉴판 사진을 올릴 동기가 있다.
- A5: 나란히 비교 화면을 단톡방 등에 공유하는 방식으로 쓴다(D9의 근거, 미검증).
- A6: 운영자 혼자 상권 2곳 × 20곳 이상의 메뉴를 직접 확인·입력할 시간이 있다.

## 인터뷰 기록
1. 주 사용자 → 추천: 가기 전에 고르는 사람, 사진은 보조 → 답: 응
2. 첫 지역 → 추천: 잘 아는 동네 한 곳(20~30곳) → 답: 인천 미추홀구, 남동구 (구 두 곳)
3. 직접 채울 범위 → 추천: 목록은 두 구 전체, 직접 채우기는 주안역·구월동 상권부터 → 답: 응
4. 비교 부위 → 추천: 삼겹살·목살만 순위, 나머지 기록만, 원산지 구분 → 답: 응
5. 맛 정보 → 추천: 자체 맛 평가 + 카카오맵 링크 → 답: 맛 평가는 하지 않음. 가게를 비교하게 하고 리뷰는 사용자가 알아서 고려 (추천안 거절)
6. 비교 방식 → 추천: 가격순 목록·지도 + 최대 3곳 나란히 비교 → 답: 추천대로
7. 데이터 입력 → 추천: 로그인 없는 사진 업로드 + 운영자 검수, 확인일 표시, OCR 제외 → 답: 추천대로, OCR은 데이터가 많이 쌓이면 추가
8. 중량 미표기 → 추천: 순위 제외, "중량 미표기" 표시, 추정 금지 → 답: 추천대로
9. 플랫폼 → 추천: 모바일 웹 + 카카오 지도 JS API → 답: 응
10. 성공 기준 → 추천: 데이터 확보(상권별 20곳)·사용(30%)·참여(사진 월 10건) → 답: 응
