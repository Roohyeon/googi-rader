## 심각도 높음

**1. 로그인이 만료된 뒤 다시 로그인하면 입력하던 내용이 사라지고, 안내도 보이지 않음**
- app.js:543: 로그인 만료 오류에 "입력한 내용은 그대로 있어요"라고 안내합니다.
- app.js:564: 같은 오류에서 `ST.authIn = false`로 바꿉니다.
- app.js:486: 다음 화면이 곧바로 로그인 화면(viewLogin)으로 바뀝니다. 이 화면은 `ST.formMsg`를 보여 주지 않습니다. 그래서 사용자는 왜 로그인 화면으로 왔는지 모릅니다. 813줄의 포커스 대상 `#form-msg`도 화면에 없습니다.
- app.js:802: 다시 로그인하면 `newForm(ST.pendingStore)`가 무조건 실행됩니다. 이때 `ST.form`이 새 폼으로 덮이고 `dirty`도 초기화됩니다. 결과적으로 입력 내용이 없어지고, 안내 문구와도 맞지 않습니다.
- app.js:956: onAuth가 로그아웃 상태를 알려 와도(예: 토큰 갱신 실패) 같은 경로로 입력 내용이 사라집니다.

**2. 가격 DB 읽기가 실패하면 이미 입력한 가게가 "정보 없음"으로 보이고, 이 상태에서 저장하면 메뉴가 중복으로 들어감**
- app.js:748: mergeOne이 오류를 조용히 삼킵니다.
- app.js:694: 그 결과 `s.gray`가 true로 남아 수정 화면이 아니라 새 입력 화면이 열립니다.
- app.js:471: 같은 이유로 storeOptions 목록에 들어갑니다. mergeDb가 실패했을 때(898줄, dbError)도 지도의 모든 가게가 회색이라 같은 문제가 생깁니다. 161줄과 357줄의 "이 가게 메뉴 입력하기"도 마찬가지입니다.
- db.js:83-86: saveMenus는 가게를 upsert한 뒤 메뉴를 insert만 합니다. 기존 메뉴가 있는지 확인하지 않으므로 같은 메뉴가 한 번 더 쌓입니다.

**3. 비동기 순서 문제: mergeDb와 savedOnly가 겹치면 저장된 가게가 전부 "정보 없음"으로 바뀜**
- app.js:886: mergeDb는 기다리기 전 시점의 STORES id로 DB를 조회합니다.
- app.js:888: 기다린 뒤에는 그 시점의 STORES를 돌면서 applyRow를 실행합니다.
- app.js:901: 그 사이 카카오 검색이 실패해 savedOnly가 STORES를 바꿔 놓아도 dbSeq는 올라가지 않습니다.
- 그래서 조회 결과에 없는 가게는 `applyRow(s, undefined)`를 거쳐 메뉴가 지워지고 gray가 됩니다(879줄).

**4. 비동기로 화면을 다시 그리면 운영자 입력칸의 포커스가 풀리고, 검색어가 지워짐**
- app.js:594-597: focusKey는 `data-act`가 있는 요소만 기억합니다. 메뉴 입력칸(data-mfield), 메모·날짜(data-field), `#find`에는 `data-act`가 없습니다.
- 그래서 아래 상황에서 render()가 돌면 포커스가 body로 빠지고 커서 위치도 사라집니다.

  - 955줄: DB.session이 끝날 때.
- app.js:509: `#find` 칸의 값은 `ST.findQ`에서 다시 채워집니다. 그런데 ST.findQ는 검색 버튼을 누를 때만 저장되므로(736줄), 입력 중이던 검색어가 지워집니다.

## 심각도 중간

**5. 저장이 한 덩어리로 처리되지 않고, 검사 순서도 뒤바뀜**
- db.js:83-86: 가게 upsert가 성공하고 메뉴 insert가 실패하면, 메뉴가 0개인 가게만 남습니다. 이미 있던 가게라면 확인일·상권만 갱신된 채로 남습니다.
- db.js:85: `bad-menus` 검사가 upsert 뒤에 있습니다. 쓰기 전에 검사해야 합니다.
- db.js:102-117: updateMenus는 삭제 → 수정 → 추가를 따로따로 요청합니다. 중간에 실패하면 일부만 반영됩니다. insert는 성공했는데 응답만 못 받은 경우, 다시 저장하면 메뉴가 중복됩니다.

**6. 권한 없는 계정으로 수정하면 "인터넷 연결 확인"이라는 엉뚱한 안내가 나옴**
- db.js:108: RLS가 수정을 막으면 오류가 아니라 0행이 돌아오고, `.single()`이 PGRST116 오류를 냅니다.
- app.js:540-546: saveErrorText에 이 경우가 없어서 SAVE_FAIL 문구(인터넷 연결 확인)로 안내됩니다.

**7. 메뉴 확인일을 검사하지 않음**
- app.js:415-424: checkForm에 날짜 검사가 없습니다.
- 날짜 칸을 비우면 `checked_at=''`가 DB로 갑니다. DB 오류가 나면 "인터넷 연결 확인"으로 안내됩니다.
- app.js:522: 미래 날짜를 막는 것은 HTML의 max 속성뿐이고, JS에서는 검사하지 않습니다.

**8. 입력한 가게 목록을 못 불러와도 "없음"으로 보이거나, "불러오는 중…"이 끝나지 않음**
- app.js:568: 불러오기 실패를 `adminStores = []`로 처리합니다. 화면에는 "아직 입력한 가게가 없어요"(481줄)와 비율 안내가 나와 오류가 가려집니다.
- app.js:698-700(editstore, newfor), app.js:679: 이 경로들은 loadAdminStores를 부르지 않습니다. 679줄은 `authIn`이 아직 false일 때(955줄 세션 확인 전)에 해당합니다. 이때 462줄과 477줄의 "불러오는 중…"이 계속 남습니다.

**9. 카카오 검색에 시간 제한이 없음**
- kakao.js:65-78: 콜백 하나라도 오지 않으면 `pending`이 0이 되지 않습니다.
- 그러면 첫 로딩이 "주변 고기집을 찾고 있어요…"(194줄)에서 멈추거나, "다시 찾는 중…"(168줄)이 계속 표시됩니다.
- 네트워크가 끊겼을 때 SDK가 콜백을 실제로 부르는지는 확인 불가입니다.

**10. 카카오 검색이 실패한 상태에서 좌표 없는 가게로 핀을 만듦**
- app.js:901: savedOnly가 만드는 가게에는 lat/lng가 없습니다.
- app.js:875 → kakao.js:96: 지도가 이미 만들어진 상태(검색만 실패)라면 livePins가 이 가게들로 `new LatLng(undefined, undefined)`를 호출합니다.
- 이때 SDK가 예외를 내는지, 잘못된 위치에 핀을 찍는지는 확인 불가입니다.

**11. 가게를 고르는 도중 폼이 사라지면 오류가 남**
- app.js:693-696: mergeOne이 끝나기 전에 로그아웃하거나(713줄 `ST.form = null`) 화면을 떠나면 `ST.form.store`에서 TypeError가 납니다. 처리되지 않은 Promise 오류입니다.

**12. "다시 불러오기" 버튼이 카카오 검색을 다시 하지 않는 경우가 있음**

- 카카오 검색은 재시도하지 않아 "카카오 오류" 배너가 그대로 남습니다.

**13. 즐겨찾기 가격을 못 불러와도 아무 표시가 없음**
- app.js:953: `.catch(() => {})`로 오류를 버립니다.
- 그래서 즐겨찾기 화면에 "아직 메뉴를 확인하지 않은 가게예요"(328줄)가 나옵니다. 오류인데 데이터가 없는 것처럼 보입니다.

**14. 로그인 오류 안내가 부정확함**

## 확인 불가 (코드만으로는 판단할 수 없음)

1. **지도 검색이 계속 반복될 위험**: 화면을 그릴 때마다 mount가 relayout과 setCenter를 부릅니다(kakao.js:50-55). 이것이 idle 이벤트를 일으키면, 검색 → 결과 → render → idle → 검색이 0.5초 간격으로 계속 돕니다. 카카오 SDK가 같은 좌표로 setCenter할 때 idle을 내는지에 달려 있습니다. 실제로 그렇다면 키워드 할당량을 빠르게 씁니다.
2. **`checked_at`이 null일 수 있는지**: null이면 calc.js:44의 `ymd.split`에서 예외가 나고, 라벨 카드(app.js:101)를 그리다 화면 전체가 멈춥니다. DB 스키마에 NOT NULL이 걸려 있는지는 확인 불가입니다.

참고로 화면에 넣는 값은 대부분 esc로 처리되어 있었습니다. 이스케이프 없이 들어가는 값은 고정 상수와 숫자뿐이라 XSS 문제는 찾지 못했습니다.

## 고기 레이더 app/ 보안 점검 결과

**요약:** 6개 항목 가운데 5개는 통과했고, 6번만 "위험(낮음)"입니다. 카카오 지도 SDK를 버전 고정 없이 불러오는데, 카카오가 버전 고정 주소를 제공하지 않아서 생기는 문제라 받아들일 만한 수준입니다. 아래 "확인 불가" 2건은 Supabase 대시보드에서 직접 봐야 합니다. 파일은 하나도 고치지 않았고, app/config.js는 열지 않았습니다.

### 1. 비밀 키가 app/ 안에 있는지: 통과
- config.js와 vendor를 뺀 app/ 전체에서 비밀 키 모양의 문자열을 찾아봤고, 하나도 나오지 않았습니다.
  - 찾은 모양: `sb_secret_`, JWT(`eyJ…`), `sk_live/test_`, AWS·Google 키, `PRIVATE KEY`, 결제 서비스 이름(toss, portone, stripe, imp_).
- app/config.example.js:8, 11, 15에는 공개용 키 3개의 빈칸만 있습니다(카카오 JS 키, Supabase URL, Publishable key).
- app/js/db.js:14-16은 `sb_secret_` 키나 service_role JWT가 들어오면 연결하지 않고 멈춥니다. 좋은 장치입니다.

### 2. config.js가 .gitignore에 있는지, git에 올라간 적이 있는지: 통과

### 3. 키 값을 화면이나 콘솔에 출력하는지: 통과
- 콘솔 출력은 app/js/app.js:893 한 곳뿐입니다. 오류 메시지(`e.message`)만 출력하고 키는 출력하지 않습니다.

### 4. DB 쓰기가 로그인한 운영자에게만 허용되는지: 통과(실제로 막는 곳은 DB 규칙)
화면 쪽 제한(`ST.authIn`에 따라 버튼을 숨김, app.js:161, 356, 486)은 보기용일 뿐입니다. 실제로 막는 것은 DB 규칙이고, 그 규칙이 제대로 되어 있습니다(dev/googi-radar/sql/01-schema.sql 기준).
- **로그인 안 한 사용자(anon):** 줄 74에서 모든 권한을 거둔 뒤, 줄 76-77에서 읽기만 다시 줍니다. anon에게는 쓰기 권한 자체가 없습니다.
- **로그인한 사용자:** 줄 79-80에서 쓰기를 "시도"할 수는 있게 하고, 줄 89-94의 RLS 규칙이 `private.is_admin()` 통과자만 추가·수정·삭제하게 합니다.
- **운영자 목록:** `private.admins` 표는 RLS가 켜져 있고 규칙이 없으며 모든 권한을 거뒀습니다(줄 21-22). 화면에서 운영자 목록을 읽거나 바꿀 수 없습니다.
- **운영자 확인 함수:** `is_admin()`은 security definer에 `search_path = ''`이고, anon은 실행할 수 없습니다(줄 24-34).
- **사진 저장소:** 비공개 버킷이고, 보기·올리기·바꾸기·지우기 모두 운영자만 됩니다(줄 97-103).
- 값의 길이와 범위 제한, `place_url` 모양 검사도 DB에 있습니다(줄 39-62, 05-more-parts.sql:3-5).

**참고(낮음):** 01-schema.sql:79가 `photo_path` 칸 읽기를 로그인한 계정 전체에 줍니다. 운영자 외 계정이 있으면 사진 파일 경로를 볼 수 있습니다. 사진 파일 자체는 저장소 규칙 때문에 받을 수 없어서 피해는 작습니다.
- 고치는 방법: 이 grant를 빼고, `photo_path` 조회는 운영자 전용 RLS 규칙이나 security definer 함수로 옮깁니다.

**확인 불가(대시보드에서 확인해야 함):** Supabase > Authentication > Sign In / Providers의 "Allow new users to sign up"이 꺼져 있는지 SQL만으로는 알 수 없습니다. 켜져 있어도 RLS 덕분에 쓰기는 막히지만, 위 `photo_path` 노출이 생기니 꺼 두기를 권합니다. 04-add-admin.sql처럼 운영자를 직접 만드는 방식이라 가입 기능은 필요 없습니다.

- **참고:** Google Fonts CSS(index.html:17)도 버전 고정이 없지만, 스크립트가 아니라 스타일이고 CSP가 출처를 제한합니다. 위험도가 매우 낮습니다.

### 정리
**꼭 고칠 것** (데이터 중복·손실, 수용 기준 실패, 앱이 멈추는 오류)
1. 가격 정보를 못 불러온 상태에서 입력하면 메뉴가 중복 저장될 수 있음 + 저장이 한 덩어리가 아님 (코드 2·5)
2. 로그인이 끊긴 뒤 다시 로그인하면 입력 내용이 사라짐 (코드 1)
3. 카카오 실패와 DB 읽기가 겹치면 가게가 "정보 없음"으로 바뀜 (코드 3)
4. 비동기로 다시 그릴 때 입력칸 포커스가 빠지고 검색어가 지워짐 (코드 4, 접근성 2.4.3)
5. R15 비교 화면에 메모가 없음 (수용 기준 실패)
6. 메뉴 확인일 검사 없음 (코드 7)
7. 카카오 검색 실패 시 좌표 없는 가게로 핀 생성, 폼이 사라진 뒤 TypeError (코드 10·11)
8. 지도를 끌기·핀치로만 움직일 수 있음 → 확대·축소 버튼, 동네 바로가기 (접근성 2.5.1 높음, 디자인 1)
9. 입력칸 테두리 대비 1.58:1, placeholder 2.95:1 (접근성 1.4.11·1.4.3)

**고치면 좋은 것**
- 오류 문구: 권한 없는 수정(PGRST116), 로그인 오류 종류, 입력한 가게 목록·즐겨찾기 가격을 못 불러왔을 때 (코드 6·8·13·14)
- 카카오 검색 시간 제한, "다시 불러오기"가 검색을 다시 안 하는 경우 (코드 9·12)
- 상태 알림을 계속 남는 #announce로, 비교 넣기·빼기 알림 (접근성 4.1.3, 디자인 7)
- 아래 선택지 화살표 이동 시 tabindex 갱신, 배경 inert (접근성 2.4.3·4.1.2)
- 뒤로 가기 버튼 이름을 직전 화면에 맞게 (디자인 3, 접근성 2.4.6)
- 값이 너무 큰 칸 표시, 가게·로그인 칸 aria-invalid, 가게 없음일 때 label 연결 (접근성 3.3.1·1.3.1)
- 넣기 후 포커스, 저장 줄이 입력칸을 가리지 않게 scroll-padding, 필터 탭 글자 11px → 12px 이상 (접근성·디자인 4)

- 보안: photo_path 읽기 권한을 로그인 계정 전체 → 운영자만 (낮음, 가입이 꺼져 있어 지금은 운영자뿐)

**의견이 갈리는 것** (기획·디자인 결정을 바꾸는 제안)
- "정보 없음" 가게를 목록 아래 접힌 묶음으로도 보여 주기 (디자인 2, 접근성 2.1.1) ↔ 기획 D22는 "목록에는 안 나옴"

- 지도 범례 "점선" 표기 (디자인 8)

**확인 불가** (통과로 치지 않음)

### 상 (데이터 손실·잘못된 저장·사용자가 막힘)

**1. 로그인이 끊긴 뒤 저장하면 "운영자 계정이 아님"으로 잘못 안내됨** (app.js:587-589, 610)
- 세션 갱신이 실패하면 클라이언트가 anon 권한으로 save_store_menus를 부르게 됩니다. 06-safe-save.sql:71이 anon 실행 권한을 회수해 두었으므로 이 경우 오류는 42501 "permission denied"로 돌아옵니다.
- 그런데 saveErrorText는 JWT 검사보다 42501 검사를 먼저 합니다. 그래서 "이 계정은 운영자로 등록되지 않아 저장할 수 없어요"가 뜹니다.
- 이때 `ST.authIn`은 true로 남고 다시 로그인하는 화면도 나오지 않습니다. 운영자는 로그아웃 후 다시 로그인해야 한다는 사실을 알 수 없습니다.
- 실제로 끊긴 세션이 anon으로 바뀌는지는 아래 확인 불가 1번에 있습니다.

**2. 이미 입력된 가게를 검색으로 고르면 쓰던 메뉴가 확인 없이 사라짐** (app.js:768)
- pickstore에서 `!s.gray`이면 바로 `editForm()`으로 폼 전체를 바꿉니다.
- 메뉴를 먼저 입력하고(dirty) 가게를 나중에 고르면 입력한 내용이 사라집니다. editstore(773)나 canceledit(777)처럼 confirm을 묻지 않습니다.

**3. 오래된 목록으로 수정 화면을 열면 메뉴가 조용히 사라지거나 남음** (app.js:411, 606 + 06-safe-save.sql:58-62)
- editForm은 `ST.adminStores`(r)를 먼저 씁니다. 저장 직후 `loadAdminStores()`는 기다리지 않고 따로 돌기 때문에, 그사이 수정을 열면 지난 메뉴 id가 그대로 들어갑니다.
- SQL은 없는 id의 update를 오류 없이 무시합니다(`m.id = x.id` 0행). 그 결과 지운 메뉴는 다시 들어가지 않고, 직전에 새로 넣은 메뉴는 p_removed에 없어서 남습니다.
- 화면은 "수정했어요"라고 알립니다. 일어날 확률은 낮지만 데이터가 틀어지는 문제입니다.

### 중 (사용자에게 보이는 오류 처리 부족)

**4. 로그인을 누르면 입력한 이메일과 비밀번호가 지워짐** (app.js:886, 492-493)
- `ST.busy = true; render()`가 로그인 폼을 다시 그립니다. viewLogin은 입력값을 보존하지 않습니다(value 없음).
- 로그인에 실패하면 이메일까지 다시 쳐야 합니다.

**5. 키가 잘못됐을 때 엉뚱한 안내가 나옴**
- 로그인 (app.js:896): `/invalid|credentials/`가 Supabase의 "Invalid API key"에도 걸려서 "이메일 또는 비밀번호가 맞지 않아요"로 나옵니다.
- 가격 읽기 (app.js:222, 993): 키가 틀리거나 권한이 없어도 "인터넷 연결을 확인해 주세요"로 나옵니다. 즐겨찾기 배너(356)와 입력한 가게 목록(518)도 같습니다.
- 카카오 (kakao.js:18-19, app.js:219): 키나 도메인 등록이 잘못돼 SDK가 실패해도 "가게 목록을 불러올 수 없어요"만 보입니다. 운영자가 원인을 짐작할 수 없습니다.

**6. 백그라운드 결과가 운영자 화면을 다시 그림** (app.js:1056, 616, 1058)
- 시작할 때의 즐겨찾기 읽기는 화면과 상관없이 `render()`를 부릅니다. loadAdminStores와 session 확인도 운영자 화면이면 다시 그립니다.
- 그래서 다음 두 가지가 생깁니다.
  - 로그인 폼에 치던 이메일과 비밀번호가 지워집니다(4번과 같은 원인).
  - 메뉴 이름을 한글로 치는 도중 다시 그려지면 입력 조합이 끊깁니다. 값은 `input` 이벤트로 ST에 들어가지만 조합 중이던 글자가 깨질 수 있습니다.

**7. 저장 직후 DB 쓰기 외의 단계가 예외를 던지면 "저장하지 못했어요"가 뜸** (db.js:91-95, app.js:601-612)
- rpc가 성공한 뒤 `uploadPhoto`가 {error}를 돌려주지 않고 예외를 던지면, saveLive의 catch가 SAVE_FAIL을 보여 줍니다. 메뉴는 이미 저장된 상태입니다.
- 사용자가 다시 저장하면 "이미 입력한 가게예요"가 나와 혼란스럽습니다. 이 일이 실제로 생기는지는 확인 불가 2번에 있습니다.

**8. 비동기 순서 경쟁(새 요청이 끝난 뒤 옛 결과가 덮어씀)**
- pickstore (app.js:765-770): seq 가드가 없습니다. A 가게를 고른 뒤 다시 찾아 B를 골랐는데 A의 응답이 늦게 오면 `ST.form.store`가 A로 바뀝니다.
- storeSearch (app.js:824-828): 두 번 연달아 찾으면 옛 결과가 나중에 와서 목록을 덮을 수 있습니다.
- locate (app.js:1032-1036): 시작할 때 위치를 묻는 동안 사용자가 "구월동"을 누르면, 나중에 온 위치 결과가 지도를 내 위치로 옮기고 `ST.where`도 덮어씁니다. 위치를 거부해도 이미 보던 목록이 "어느 동네부터 볼까요?" 화면으로 바뀝니다.
- loadAdminStores (app.js:614-617): 순서 번호가 없어 늦게 온 옛 결과가 새 결과를 덮을 수 있습니다.
- 시작 시 즐겨찾기 읽기 (app.js:1056): 그사이 저장되거나 수정된 가게 정보를 옛 응답으로 덮을 수 있습니다.
